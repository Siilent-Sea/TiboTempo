# TiboTattle 0.1.29

**Status: unreleased candidate.** These notes describe the changes being
prepared since 0.1.28. Client signing, installed-upgrade qualification,
publication and hosted deployment are separate release gates.

TiboTattle recognizes GPT-6.1 Terra as a distinct model in local usage,
API-equivalent accounting and model performance. Prices use OpenAI's
[October 26, 2026 release date](https://developers.openai.com/api/docs/changelog)
and [official model pricing](https://developers.openai.com/api/docs/models/gpt-6.1-terra),
reviewed on that date. Standard prices per million tokens are $1 for input,
$0.05 for cached input, $1.25 for cache writes and $5 for output. Batch and
Flex use half the Standard rates; Fast uses twice the Standard rates. Requests
above 272,000 input tokens use twice the input and cache rates and 1.5 times
the output rate for the whole request. Exactly 272,000 tokens stays in the
short-context band.

Cache-write comparisons retain TiboTattle's existing 30-minute retention
assumption. Twelve-hour retention and regional premiums are not represented.
Terra Ultrafast remains unpriced, and no Terra-specific Codex allowance weight
is inferred from its API prices. Existing models keep their historical price
cards and identities; earlier published model rosters do not acquire Terra
retroactively. Community views can name the model while leaving an unavailable
estimate explicit.

A detailed refresh reprocesses available Codex logs to recognize Terra in
retained usage and timing records. Replay preserves token totals and event
identities. Previously stored unknown records cannot be re-identified when
their source log has disappeared; the app keeps that uncertainty instead of
inventing a model.

Model performance defaults to the system time zone and offers a saved UTC
toggle. Daily and weekly charts, labels and hover targets follow the selected
calendar, including daylight-saving transitions and fractional offsets.
Cached reports stay tied to their time zone, so a UTC summary is not relabeled
as a local-calendar result. Exact rolling report bounds and hosted community
UTC publication retain their existing meaning.

An initial speed setting recorded after a turn starts can now qualify its
performance samples when attributable evidence establishes that it preceded
all output. Genuine mid-turn changes, conflicting or ambiguous attribution,
and unreadable evidence remain excluded from a confident speed assignment.
Reprocessing available history repairs classification without changing the
underlying timing measurements. Thanks to
[Siilent-Sea](https://github.com/Siilent-Sea) for the calendar and initial-speed
work in [PR #299](https://github.com/adamallcock/tibotattle/pull/299), preserved
and strengthened in [PR #300](https://github.com/adamallcock/tibotattle/pull/300).

Large local export verification avoids repeatedly validating the same source
metadata. Claude exports skip oversized transcript records that cannot contain
usage, while retaining limits for records that may contain usage. Quota
analysis also avoids repeated scans and sorts while preserving its calculations.

The desktop runtime advances from Electron 43.5.0 to 43.8.1. Dependency fixes
also update affected URL parsing, HTTP, and hosted test/build components,
including fast-uri, Undici, Vitest, Vite and Zod. The macOS minimum remains
macOS 14.

The client and server share the new model and price contracts, but installing
the client alone does not deploy the hosted service, recalculate community
results or repair previously accepted hosted records. Those steps require the
separate server rollout and its verification. This candidate makes no new
platform qualification claim; the existing artifact-specific limits remain
documented in [platform support](../docs/reference/platform-support.md).
